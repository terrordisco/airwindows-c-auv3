- [x] Value text doesn't track external modulation — under a host LFO (AUM), miRack CV, or any render-thread automation, a parameter's knob moved but its numeric value text stayed frozen at the last *manually-edited* value. Root cause was in the bridge: `parameterDisplayAtIndex:` asked the display processor for its display string **without first seeding it with the live value**. The display processor's internal value is only updated on the user-edit path (`setParameterValue:` / `implementorValueObserver`); external modulation lands only in `_paramValues` via the render thread, so the display query returned stale text while the knob — driven straight from the parameter observer's fresh value — moved on. (This is why it read as a "partial regression": manual edits always looked right, modulation didn't, and it wasn't miRack-specific.) Fixed by seeding `_displayProcessor->setParameter(idx, _paramValues[idx])` before reading — `_paramValues` is the single source of truth every write path updates. One line, fixes all callers; `_displayProcessor` is UI/main-thread only so it can't affect audio. Confirmed on device in AUM: knob animation and value text now move in lockstep under LFO modulation.
