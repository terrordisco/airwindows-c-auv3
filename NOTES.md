## Key Technical Decisions

### AUAudioUnit lives in the framework, not the extension
The AUAudioUnit subclass directly accesses `AirwinRegistry::registry` (C++ statics).
These statics are populated during framework load via ModuleAdd.h. If the AU class
were compiled in the extension target, it would get its own empty copy of the statics.

### Fixed 40-parameter tree
AUv3 hosts expect a stable parameter tree. We use 37 fixed slots (relabeled per effect,
addresses 0-36) + effect index (37) + input/output levels (38/39). Max is driven by
ConsoleXBuss/Channel/Pre which have 37 params each. Unused slots stay in the tree but
are hidden from the UI via `parameterCount`.

### Atomic effect switching
New effect processor created on main thread, swapped into audio thread via
`std::atomic<AirwinConsolidatedBase*>`. Old processor freed on main thread via dispatch_async.

### Extension Info.plist
- `NSExtensionPointIdentifier` = `com.apple.AudioUnit-UI` (NOT `com.apple.AudioUnit`)
- `factoryFunction` in AudioComponents = `$(PRODUCT_MODULE_NAME).AUv3ViewController`
- `NSExtensionPrincipalClass` = `$(PRODUCT_MODULE_NAME).AUv3ViewController`
- `CFBundleDisplayName` required or install fails

### AUv3ViewController
- Must be `@MainActor` for UIKit viewservice to work
- `createAudioUnit` must be `nonisolated` with `DispatchQueue.main.sync` inside

### Override layer pattern for upstream-generated data
Effect metadata (categories, blog post URLs, video URLs, long descriptions)
gets corrected via JSON resources loaded at the bridge boundary, never by
editing upstream-generated files. `ModuleAdd.h`, `awpdoc/`, and the
`autogen_airwin/` C++ classes are all regenerated by airwin2rack's
`updateToLatest.sh`; direct edits would be wiped.

The pattern:
- **Resource JSON** in `AirwindowsDSP/Resources/`
  (`category_overrides.json`, `effect_links.json`)
- **Loader in `AirwindowsBridge.mm`** caches the JSON once on first access
- **Lookup helpers** like `AirwindowsCategoryFor(name, registryDefault)`
  used wherever we surface that field — `allEffects`, `effectInfoAtIndex:`,
  `currentEffectCategory` on the AU subclass, etc.
- **For data that's appended** (descriptions in `awpdoc/<Effect>.txt`),
  scripts only WRITE files that don't already exist, never overwrite

Roadmap "Manual-edit safeguard" (under Auto-update Later) extends this:
when the auto-sync pipeline lands, it must keep a manifest of files we've
hand-edited or scraped, and flag conflicts rather than silently
overwriting.

### State persistence — preset format vs session format
Two delivery paths for `setFullState:` with different dictionaries:
1. **AUM session save:** dict has BOTH our custom keys (`effectName`,
   `effectIndex`, `parameterValues`, `inputLevel`, `outputLevel`) AND
   super's standard data blob. We can read effectName directly.
2. **`.aupreset` and AUM preset save:** host strips non-standard keys
   when serializing the preset. Only super's data blob is in the dict.
   We must read the target effect from the parameter tree (after super
   has restored it).

`[super setFullState:]` MUST be called first — it populates the parameter
tree silently (does NOT fire the implementor value observer; Apple uses a
private originator). Our code then runs the side effects super skipped:
calling `selectEffectAtIndex:` to instantiate the right processor and
applying parameter values from either source.

Saving (`fullState`) writes BOTH our custom keys and lets super contribute
its data blob — that way path 1 hosts can use the friendlier custom keys
while path 2 hosts still recover via the tree blob.

**Cubasis "No effect selected" on reopen (2026-06-01) — a UI-sync race, NOT
a persistence failure.** Device `os_log` (Console.app, subsystem
`com.terrordisco.airwindows.consolidated`) proved Cubasis *was* restoring
correctly: it calls `setFullStateForDocument:` with our custom keys intact
(`effectName=Distance`, `effectIndex=161`) and the AU resolved the right
effect. The bug was timing:

1. Cubasis mounts the plugin; the view model's `configure()` reads
   `currentEffectIndex` → **-1** (nothing restored yet) → UI shows
   "No effect selected".
2. Cubasis restores state ~270ms LATER. Apple **does not fire parameter
   observers during state restore**, and our code skipped `selectEffectAtIndex`
   (the index already matched), so the view model never learned the effect
   loaded. It stayed on its stale read.

Fixes:
- AU posts `AirwindowsAudioUnitDidRestoreState` (main thread) at the end of
  `-applyRestoredStateFromDictionary:`; the view model observes it and calls
  `refreshEffectInfo()`. Host-agnostic — covers any host that restores after
  the view mounts.
- Launch logic (`AirwindowsAUView`): open the browser only when nothing is
  selected; an `onChange(of: effectIndex)` dismisses the auto-opened browser
  when a late restore brings in an effect, so you land on the param page.
- Added matching `fullStateForDocument`/`setFullStateForDocument:` overrides.
  AUM uses plain `fullState`; Cubasis uses the `*ForDocument` variant. The
  setter calls the MATCHING super so the param-tree blob restores, then runs
  the shared `applyRestoredStateFromDictionary:`.

Lesson: support BOTH the document and non-document state APIs, and never
assume a one-shot read at `configure()` sees restored state — the host may
restore *after* the view is live. A blank UI over a correctly-loaded engine
is a sync bug, not a persistence bug; device `os_log` is the fastest way to
tell them apart.

### Scrollable parameter + description field (`ParameterScrollView`)
- The effect workspace packs draggable faders/pots and longform description text
  into one tall column. With a normal ScrollView a single-finger fader/pot drag
  and a scroll are indistinguishable, so they fight — a tweak can scroll instead.
- **Final model:** empty space scrolls with one finger; a touch that *starts on a
  control* drives that control and never scrolls. `ParameterScrollView` (in
  AirwindowsUI) wraps the grid + description as one field; faders/pots are tagged
  `.scrollDragControl()`. Grid `rowSpacing` widened to 32 so there's empty space
  to grab between controls.
- **Why not two fingers (scrubbed):** the obvious idea — reserve scrolling for
  two fingers so one finger always adjusts — breaks a core mixing gesture:
  grabbing two pots/sliders at once. Any two-finger scroll would hijack it. So
  scrolling is single-finger-on-empty-space only.
- Implementation: stock SwiftUI `ScrollView` (native momentum/bounce/indicators/
  sizing). A zero-size probe walks up to the backing `UIScrollView`; a
  `TouchDownObserver` (a UIGestureRecognizer that reports the first touch's
  location then immediately `.failed`s, so it never competes) sets the pan's
  `minimumNumberOfTouches` to a value out of reach (6) the instant a touch lands
  on a registered control region, and back to 1 for empty space. Raising it
  *disables* scrolling for that gesture rather than "requiring more fingers", so
  two fingers on two controls both adjust — nothing scrolls. Control frames
  tracked via a weak `NSHashTable`.
- Dead ends along the way (kept as a warning): (1) introspect a SwiftUI
  ScrollView + min-touches=2 → two fingers scrolled text but not over controls
  (SwiftUI's gesture wins exclusively over the pan). (2) Custom UIScrollView +
  `SimultaneousPanDelegate` proxy to force simultaneous recognition → **crashed**
  with `NSInvalidArgumentException: UIScrollView's built-in pan gesture
  recognizer must have its scroll view as its delegate` — you may not replace the
  pan's delegate. Both abandoned when the two-finger idea itself was scrubbed.
- Scoped to this container only: browser/sidebar lists keep ordinary scrolling.
  No-parameter effects keep their plain single-finger description ScrollView.
- macOS build path falls back to a plain `ScrollView` under `#if canImport(UIKit)`.

## Recent Changes (2026-05-13)

### Stepped / popup parameters — dots + snap-on-release
- Chris's "popup parameters" (DSP-side `(VstInt32)(X * N.999)` casts) are now
  rendered as a discrete control on both the slider and the pot: N small
  dots equally spaced along the track (slider) or arc circumference (pot),
  free travel during drag, snap to the nearest case center on release.
- Detection is runtime, not metadata: `AirwindowsAudioUnit
  parameterStepCountAtIndex:` sweeps `getParameterDisplay` over 257 samples
  using the non-render `_displayProcessor`, restores the original value, and
  returns the unique-display-string count if it lands in 2…32, else 0
  (continuous). Sampling happens once per effect switch inside
  `refreshEffectInfo`. ~68 effects use this pattern; e.g. Cabs/CabType has 6,
  Cans/A and Focus/Mode have 5, Dirt/E has 4, Monitoring/A has 17.
- Snap math: bin k center = `(k + 0.5) / N` in normalized space, which the
  upstream cast `(VstInt32)(A * (N-1).999)` reliably truncates back to k.
- Plumbing: `parameterStepCounts: [Int]` lives on the ViewModel, threaded
  through `EffectDetailView` → `ParameterGrid` → `ParameterRow` →
  `LinearFader` / `RotaryPot`. All have a `stepCount: Int = 0` opt-in
  parameter; zero = unchanged continuous behaviour.
- `RotaryPot` step rendering: dots are drawn LAST in the ZStack (above the
  value arc) so they remain visible on both the lit (`Color.primary`) side
  and the unlit gray track — first pass rendered them between the layers,
  which left them occluded on the filled side. Fill uses
  `AirwindowsPalette.surface(scheme)` so each dot reads as a punched-out
  hole against either stroke, in both light and dark themes. Dot diameter
  scales with stroke weight (`max(2.5, min(strokeWeight*0.8, size*0.06))`).
- `RotaryPot` interaction: when `stepCount >= 2` the unity-magnet detent at
  1.0 is suppressed; otherwise the magnet would fight the per-step snap on
  release. The 0…2 range In/Out level pots are not stepped so they keep the
  detent unchanged.

### "This effect has no parameters" empty state
- 48 of the 504 effects have zero parameters (`kNumParameters = 0`) — they
  are fixed-character processors: dithers (HighGlossDither, NaturalizeDither,
  …), Console8 fixed buses, clip-only utilities, mono/stereo helpers, tape
  desks, etc.
- `EffectDetailView` previously skipped the grid silently for these, leaving
  a blank slab between the chip row and the description. Now there's an
  explicit centered placeholder in the parameter region — same
  `font(.system(size: 17)).foregroundStyle(.secondary)` styling as the
  browser's "No effect selected" message, with `VStack { Spacer(); Text;
  Spacer() }` inside a `frame(maxWidth: .infinity, maxHeight: .infinity)`
  so it occupies the full grid slot.

## Recent Changes (2026-05-08)

### State persistence — `setFullState:` ordering fix
- **Bug:** Loading an AUM preset or AUv3 `.aupreset` showed the
  "Pick an effect" placeholder instead of the saved effect. AUM session
  save worked because session restore includes our custom `effectName` key;
  preset/`.aupreset` formats strip non-standard keys, leaving only super's
  standard data blob.
- **Root cause:** `[super setFullState:]` restores the parameter tree
  silently — it does NOT fire the implementor value observer (Apple uses a
  private originator that excludes implementer observers). So the saved
  `effectIndex` value (param 37) was being written to the tree, but
  `selectEffectAtIndex:` was never called, leaving `_effectIndex = -1`.
- **Fix in `AirwindowsAudioUnit.mm` setFullState:**
  1. Call `[super setFullState:]` FIRST (was last) — populates parameter tree.
  2. Snapshot saved param values from custom array, or fall back to the tree.
  3. Resolve target effect: custom `effectName` key → custom `effectIndex` key
     → `effectIndexParam.value` from the tree.
  4. Call `selectEffectAtIndex:` ourselves to do the side effect that super
     skipped.
  5. Apply saved param values, overriding the new effect's defaults that
     `selectEffectAtIndex:` just installed.
  6. Levels: prefer custom keys, fall back to param tree.

## UI Design Direction (from Figma mockups 2026-04-08)

**Constraint:** Every piece of content shown to the user must come from the
airwin2rack source. No hand-written copy. A new effect ships each week and we
can't maintain manual descriptions/helpers per effect.

**What we have from source** (safe to use):
- Effect name, category, `whatText` tagline, `awpdoc/<Effect>.txt` full description
- Parameter names, labels (units), display strings
- `catChrisOrdering`, `firstCommitDate`, collections, `isMono`, nParams

**Architecture — three main views:**

## RotaryPot Design Spec
Implemented in `Packages/AirwindowsUI/Sources/AirwindowsUI/RotaryPot.swift`.

- **Arc range:** 270° sweep from 135° (7:30) clockwise to 405° (4:30)
- **Ring thickness:** `max(1.6, size * 0.055)` — scales with pot size
- **Arc radius:** `size / 2 - strokeWeight / 2 - 1` (centerline, inset for stroke)
- **Indicator inner radius:** `arcRadius * 0.40`
- **Colors:** track is `Color.secondary.opacity(0.35)`, value/indicator is `Color.primary`
- **Key trick:** the value arc and the radial indicator are drawn as ONE
  continuous Path — arc followed by a line inward to the inner point — with
  `lineJoin: .round`. This makes the 90° corner render as a smooth rounded
  turn instead of a visible T-junction between two separate strokes.
- **Label above, value text below**, both using `Color.secondary`, tight 2pt
  vertical spacing on the container VStack.
- **No interaction yet** — it's a read-only view. Drag gesture for user input
  comes later.

## Lessons: Figma plugin vs SwiftUI for custom shapes
Spent time drawing the pot in Figma via the plugin API before switching to
SwiftUI. Writing this down so we don't repeat it:

- **Figma's `vectorPaths` does NOT support SVG's `A` (arc) command.** Only
  `M`, `L`, `C`, `Q`, `Z`. Arcs must be approximated with cubic Beziers
  (≤90° per segment).
- **`EllipseNode.arcData` with `innerRadius < 1`** creates a ring SHAPE, and
  then strokes outline that shape → at large sizes you get a visible double
  outline instead of a clean ring. Must draw the arc as a stroked vector path.
- **Vector node x/y positioning** is auto-computed from the path bounding
  box. Setting `v.x = 0; v.y = 0;` AFTER setting `vectorPaths` shifts the
  path by `-bbox.topLeft`, which is fine for large-bbox shapes (arcs) but
  catastrophic for small-bbox shapes (short lines) that then end up in the
  wrong place.
- **SwiftUI has `Path.addRelativeArc(center:radius:startAngle:delta:)`** which
  takes a signed delta. Positive delta = visually clockwise in SwiftUI's
  y-down coordinate system. One line of code, no Bezier math, pixel-perfect.
- **Takeaway:** for custom-drawn components (pots, meters, waveforms),
  prototype directly in SwiftUI with `#Preview`. Use Figma for layout
  composition, typography, color decisions, and specs for non-coders.
